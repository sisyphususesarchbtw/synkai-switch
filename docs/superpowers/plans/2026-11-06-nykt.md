# NYKT Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Native execution is the recommended default for this tightly coupled solo deadline.

**Goal:** Build a real Switch workflow that rejects a false AI-written fix and verifies a real fix with frozen before-and-after evidence.

**Architecture:** Switch carries all human-agent and agent-agent collaboration. A local FastAPI service maintains case state and drives a separately controlled Docker verifier; a React UI displays the resulting evidence and source-room activity. One allowlisted project and one active run keep the first build bounded.

**Tech Stack:** Python 3.12+, FastAPI, Pydantic, SQLite, pytest, Docker; Node 22+, React, TypeScript, Vite. Pin exact versions tested in Task 1.

**Spec:** ../specs/2026-11-06-nykt-design.md; also read ../../../PRODUCT.md and ../../../DESIGN.md from this file's directory.

## Global Constraints

- Product NYKT; team Stillpoint; tagline Clarity, earned.; dark Zen interface per DESIGN.md.
- One trusted local operator, one allowlisted repository and one active verification at a time. Backend and UI bind to loopback by default.
- Mattermost via Switch first. Discord after core acceptance only. No WhatsApp integration claim.
- Switch is the only collaboration/handoff path. Browser UI is a view plus authenticated commands to the room, not a parallel agent messaging system.
- Budget: 60 seconds per container run, 1 CPU, 512 MiB memory, 64 processes, 64 KiB stdout/stderr per stream with explicit truncation metadata.
- At most one initial attempt plus one repair candidate. Stop and ask the human if that fails.
- Secrets never enter the frontend bundle. No automatic public comments, merges, deployments or outbound messages outside the configured project room.

## Review Focus

1. Forged/quoted human approval: only an actual allowlisted Switch sender can freeze a check (Task 2).
2. Candidate controls test discovery/config: verifier uses its own harness and treats zero collection/skips/setup failure as inconclusive (Task 3).
3. Reconnect or duplicate event: one transition and run; persist cursor/outbox and do not re-register agent (Task 4).
4. New code after verification: previous result remains historical and current candidate is explicitly stale (Tasks 2 and 5).
5. Offline or missing artifacts: show incomplete evidence; never synthesize success or accept an undispatched command (Tasks 4 and 5).

## Plan self-review

All design boundaries map to Tasks 1–8. Review Focus failures are assigned to tests. NYKT UI SSE is deliberately distinct from Switch WebSocket. The first implementation task resolves missing Docker/provider access rather than assuming it exists. Independent builder review found three material gaps: actual Fixer process isolation, operator-frozen repository/base identity, and receiver-side command deduplication after outbox retries. Each is now specified with owning tasks and checks. Product code has not been written. The plan can be executed natively after the selected design is reviewed.
